Mesmo motor, outro painel

Pense num carro com dois painéis. No terminal, você dirige escrevendo ordens. Na aba Code do Desktop, dirige apertando botões. O motor é o mesmo: o Claude lê os arquivos da pasta, cria e altera arquivos, roda tarefas e pede sua autorização antes de agir.

Os dois leem as mesmas instruções e configurações guardadas no seu computador. Uma habilidade (skill) criada para o terminal aparece no Desktop, e vice-versa.

Você não precisa instalar o Claude Code de terminal para usar a aba Code: ele já vem dentro do aplicativo.

Como abrir a aba Code

  1. Baixe o aplicativoEm claude.ai/download, para Windows 10 ou mais novo, ou macOS 13 ou mais novo. Instale como qualquer programa.
  2. Entre na sua contaÉ preciso um plano pago: Pro, Max, Ultra, Team ou Enterprise. O plano gratuito abre o chat, mas não a aba Code.
  3. Clique em CodeFica no alto da barra lateral. Se aparecerem só ícones, passe o mouse por cima para ver os nomes.
  4. Escolha a pastaNo seletor de ambiente, escolha Local e depois Open folder… Use uma pasta só para isso.
  5. Faça o primeiro pedidoPor exemplo: “Crie um CLAUDE.md com instruções para esta pasta”.

Só de um lado

Aqui está o que não tem equivalente do outro lado. Saber disso evita procurar no Desktop um botão que não existe.

só no Desktop

O que o aplicativo acrescenta

  • Não precisa instalar nada além do appO Claude Code já vem dentro do aplicativo. Não precisa de Node.js nem do programa de terminal.
  • Ver as mudanças na telaO indicador +12 −1 abre a lista do que mudou. Passe o mouse numa linha e clique no + para deixar um comentário.
  • Anexar imagens e PDFsArraste o arquivo para a conversa. No terminal isso não existe.
  • Ver o site funcionandoO Claude pode abrir o site que está criando num navegador dentro do próprio app, para conferir o resultado.
  • Terminal embutidoSe quiser digitar algo, abra um terminal dentro do app com Ctrl + `.
  • Sessão na nuvem, por SSH ou no WSLA sessão pode rodar nos computadores da Anthropic e continuar mesmo com o app fechado. O uso conta no limite do seu plano, sem cobrança à parte.
  • Conectores por telaLigar o Claude a outros serviços clicando, sem editar arquivo de configuração.
só no terminal

O que continua exclusivo do terminal

  • Scripts e automaçãoRodar o Claude sem conversa, dentro de um script (-p, --output-format). O Desktop é só interativo.
  • Equipes de agentesVários Claudes trabalhando juntos como equipe (agent teams) existem só no terminal.
  • Modo dontAskEsse modo de permissão não aparece no seletor do Desktop.
  • Shift + Tab para trocar o modoNo Desktop, o atalho não funciona; use o seletor embaixo da caixa.
  • Liberar ou bloquear ferramentas por sessãoAs opções --allowedTools e --disallowedTools não existem no app. As regras salvas nas configurações continuam valendo.
  • Painéis interativosComandos que abrem um painel no terminal, como /permissions, respondem no Desktop que não estão disponíveis.

São duas cópias do Claude Code. O Desktop traz a própria cópia, que pode estar numa versão diferente da do terminal. Atualizar um não atualiza o outro. Por isso, um recurso novo pode aparecer primeiro de um lado só.

Dá para usar os dois

Do terminal para o app

No terminal, digite /desktop. A mesma conversa continua no aplicativo, sem virar cópia. Funciona no Mac e no Windows de 64 bits (x64), com login de assinatura.

Retomar no app

Na caixa de pedido do Desktop, digite /resume para escolher uma sessão que você começou no terminal.

Uma configuração só

Skills, CLAUDE.md, hooks e MCP ficam nos mesmos arquivos. Configure uma vez e use dos dois lados.

Perguntas frequentes

As dúvidas de quem está trocando o terminal pelo aplicativo, ou usando os dois.

Preciso instalar o Claude Code de terminal para usar a aba Code?

Não. O aplicativo já traz o Claude Code dentro dele. Se um dia quiser usar o comando claude no terminal, ele se instala à parte; há um guia passo a passo em Instale o Claude Code no seu computador.

É de graça?

Não. A aba Code exige um plano pago: Pro, Max, Ultra, Team ou Enterprise. Com o plano gratuito, o aplicativo abre o chat, mas pede para assinar um plano ao clicar em Code.

Minhas skills, CLAUDE.md e configurações valem nos dois?

Sim. O terminal e o Desktop leem os mesmos arquivos: CLAUDE.md no projeto, as skills em ~/.claude/skills/ e as configurações em ~/.claude/settings.json. Algumas opções se comportam diferente na aba Code.

Configurei um servidor MCP no terminal. Ele aparece no Desktop?

Sim, se estiver em ~/.claude.json ou em .mcp.json. O contrário nem sempre vale: o Desktop também lê a configuração do app de chat (claude_desktop_config.json), e o terminal não lê esse arquivo.

Atualizei o Claude Code do terminal. O Desktop também atualizou?

Não. A aba Code usa a própria cópia do Claude Code, que se atualiza junto com o aplicativo. Cada um tem a sua versão.

Aperto Shift + Tab e nada acontece. Está quebrado?

Não. No Desktop, esse atalho não troca o modo de permissão. Use o seletor de modo, na linha embaixo da caixa de pedido.

Comecei uma conversa no terminal. Posso continuar no Desktop?

Sim, de dois jeitos. No terminal, digite /desktop, que funciona no Mac e no Windows de 64 bits com login de assinatura. Ou, no Desktop, digite /resume na caixa de pedido e escolha a sessão.

Preciso instalar o Git no Windows?

Só para sessões com Worktree ligado. Para o uso comum, não. Se o aplicativo pedir o Git sem você usar Worktree, atualize o aplicativo: versões antigas pediam sempre.

Sessões na nuvem custam a mais?

Não há cobrança separada pelo computador da nuvem: o uso conta no limite do seu plano. A vantagem é que a sessão continua mesmo se você fechar o aplicativo.

E o “voltar atrás” do terminal (Esc duas vezes ou /rewind)?

No terminal, /rewind ou Esc duas vezes voltam a conversa e os arquivos a um ponto anterior. A documentação do Desktop não diz se isso funciona na aba Code. Lá, Esc interrompe o Claude. Na dúvida, trabalhe numa cópia da pasta ou com o Git.

É seguro?

Os cuidados são os mesmos do terminal. 1. Abra sempre uma pasta própria, nunca a pasta pessoal inteira. 2. Leia cada pedido de permissão antes de aceitar e deixe o modo Bypass desligado. 3. Não use documentos confidenciais nem dados pessoais de outras pessoas sem autorização de quem responde por eles.
